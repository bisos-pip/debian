** +
** BISOS Python Command-Services for interfacing with Debian systemd.
** Each service is specified by a =*-sysd.pcs= planted file that defines the unit file content
** and lifecycle hooks. The seed commands write, enable, and manage the systemd unit.
** -B|

####+BEGIN: blee:bxPanel:foldingSection :outLevel 1 :sep t :title "Architecture: 3-Layer Seed/Plantation Pattern" :anchor "Architecture" :extraInfo ""
* /[[elisp:(beginning-of-buffer)][|^]]  [[elisp:(blee:menu-sel:navigation:popupMenu)][Ξ]] [[elisp:(delete-other-windows)][|1]]/
* [[elisp:(show-all)][(>]]  _[[elisp:(blee:menu-sel:outline:popupMenu)][±]]_  _[[elisp:(blee:menu-sel:navigation:popupMenu)][Ξ]]_       [[elisp:(outline-show-subtree+toggle)][| *Architecture: 3-Layer Seed/Plantation Pattern:* |]] <<Architecture>>   [[elisp:(org-shifttab)][<)]] E|
####+END
** +
** Layer 1: Configuration Definition Layer (=-*-sysd.pcs=)
   - Defines a =sysdUnitFileFunc()= that returns the systemd INI-format unit file as a string
   - Optionally defines =preFunc()= and/or =postFunc()= callables (Python-level lifecycle hooks)
   - Calls =systemd_seedInfo.setup()= to register all metadata into the singleton
   - Example skeleton:
     #+begin_src python
     from bisos.debian import systemd_seedInfo
     from bisos.debian import systemd_seed as systemd_seed  # noqa
     from bisos.basics import pathPlus

     def sysdUnitFileFunc() -> str | None:
         if (execPath := pathPlus.whichBinPath("myservice")) is None: return None
         return f"""
     [Unit]
     Description=My Service
     After=network.target
     [Service]
     ExecStart={execPath} --flag
     Restart=on-failure
     [Install]
     WantedBy=multi-user.target
     """

     def preFunc():
         pass  # runs before ensure() enable+start; closes over .pcs context

     def postFunc():
         pass  # runs after ensure() enable+start; closes over .pcs context

     systemd_seedInfo.setup(
         seedType="sysdSysUnit",
         sysdUnitName="myservice",
         sysdUnitFileFunc=sysdUnitFileFunc,
         preFunc=preFunc,
         postFunc=postFunc,
     )
     #+end_src

** Layer 2: Metadata Storage Layer (=systemd_seedInfo.py=)
   - =SystemdSeedInfo= is a *singleton* holding all configuration metadata registered by a =.pcs= file
   - Current properties:

     | Property          | Type               | Purpose                                                   |
     |-------------------+--------------------+-----------------------------------------------------------|
     | =seedType=        | =str \| None=      | Unit class: ="sysdSysUnit"=, ="sysdUserUnit"=, etc.       |
     | =sysdUnitName=    | =str \| None=      | Base name of the unit (without =.service= suffix)         |
     | =sysdUnitFileFunc= | =Callable \| None= | Returns the systemd unit file content as a string         |
     | =examplesHook=    | =Callable \| None= | Hook for providing usage examples in the seed             |
     | =preFunc=         | =Callable \| None= | Called at Python level *before* enable+start in =ensure()= |
     | =postFunc=        | =Callable \| None= | Called at Python level *after* enable+start in =ensure()=  |

** Layer 3: Processing/Implementation Layer (=bifSystemd_csu.py=)
   - =ConfigFile_sysdUnit= reads =sysdUnitFileFunc()= and writes the unit file to
     =/etc/systemd/system/{name}.service= via the =configFile= pattern (=--cls=configFile_sysdUnit=)
   - =SysUnit= class provides systemd management operations:
     - =ensure()= — writes file, calls =preFunc=, reloads daemon, restarts, enables, calls =postFunc=
     - =reload()=, =start()=, =stop()=, =restart()=, =enable()=, =disable()= — =systemctl= wrappers
   - =UserUnit= and =SocketUnit= follow the same class structure but manage user-scope and socket units respectively

** Data Flow

   #+begin_src
   *-sysd.pcs  →  systemd_seedInfo (singleton registry)  →  bifSystemd_csu (write + manage)
   #+end_src

** -B|

####+BEGIN: blee:bxPanel:foldingSection :outLevel 1 :sep t :title "Pre/Post Hook Semantics" :anchor "Hooks" :extraInfo ""
* /[[elisp:(beginning-of-buffer)][|^]]  [[elisp:(blee:menu-sel:navigation:popupMenu)][Ξ]] [[elisp:(delete-other-windows)][|1]]/
* [[elisp:(show-all)][(>]]  _[[elisp:(blee:menu-sel:outline:popupMenu)][±]]_  _[[elisp:(blee:menu-sel:navigation:popupMenu)][Ξ]]_       [[elisp:(outline-show-subtree+toggle)][| *Pre/Post Hook Semantics:* |]] <<Hooks>>   [[elisp:(org-shifttab)][<)]] E|
####+END
** +
** Pre/post hooks are *Python-level* callables, not systemd units.
** They are invoked by =SysUnit.ensure()= during the Python execution of the seed:
   - =preFunc()= is called *before* =serviceFileVerify / reload / restart / enable=
   - =postFunc()= is called *after* the full enable+start sequence completes
** Hooks receive *no arguments*. The =.pcs= file closes over whatever context it needs.

** Intended use cases:
   - Creating directories or config files that =ExecStart= reads on first launch
   - Setting permissions on paths before the service starts
   - Recording that a preparation step has occurred (e.g. via a flag file)

** What hooks are NOT for:
   - Persistent side effects that should survive reboots — use a dedicated =Type=oneshot=
     systemd unit with =RemainAfterExit=yes= for those (e.g. =airflow-db-sysd.pcs=
     running =airflow db migrate=)
   - Anything that systemd itself should track or order — put it in a unit with
     =Requires== / =After== dependencies instead

** Distinction: Python hook vs. systemd oneshot
   | Criterion              | =preFunc= hook                    | Dedicated oneshot unit              |
   |------------------------+-----------------------------------+-------------------------------------|
   | Recorded by systemd    | No                                | Yes (journal + RemainAfterExit)     |
   | Survives reboots       | No (runs only at =ensure= time)   | Yes (systemd tracks completion)     |
   | Ordering with other units | Not visible to systemd         | Declared via =Requires= / =After=   |
   | Use case               | ExecStart preparations            | DB migration, initialisation tasks  |

** -B|

####+BEGIN: blee:bxPanel:foldingSection :outLevel 1 :sep t :title "Systemd Symlink Lifecycle" :anchor "Symlinks" :extraInfo ""
* /[[elisp:(beginning-of-buffer)][|^]]  [[elisp:(blee:menu-sel:navigation:popupMenu)][Ξ]] [[elisp:(delete-other-windows)][|1]]/
* [[elisp:(show-all)][(>]]  _[[elisp:(blee:menu-sel:outline:popupMenu)][±]]_  _[[elisp:(blee:menu-sel:navigation:popupMenu)][Ξ]]_       [[elisp:(outline-show-subtree+toggle)][| *Systemd Symlink Lifecycle:* |]] <<Symlinks>>   [[elisp:(org-shifttab)][<)]] E|

** +
** =systemctl enable= reads the =[Install]= section of the unit file.
** For =WantedBy=multi-user.target=, it automatically creates a symlink in:
**   =/etc/systemd/system/multi-user.target.wants/{name}.service=
** =systemctl disable= removes the symlink. Neither requires manual =pathlib= management.

** Key implication:
   - The unit file's =[Install]= section with =WantedBy= is sufficient
   - =SysUnit.ensure()= and =SysUnit.remove()= do not need to manage symlinks manually
   - Same applies to =UserUnit= and =SocketUnit= (=sockets.target.wants/=)
